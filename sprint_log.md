- [x] [LL-055](tasks.md#LL-055) **Session B — broadcast fanout on a dedicated FreeRTOS task (May 15) — LL-055 fix #3 of N, bug-doc fix #2.** The architecturally-right fix from [post-mini-sprint-bugs.md #1](docs/post-mini-sprint-bugs.md): inbound dispatch on the httpd task must not block on outbound socket writes. **Why it still mattered after Session A's debounce + the May 14 fix #1:** the 30ms debounce timer was moving the *trigger* off-thread (esp_timer task ran the fanout), but `httpd_ws_send_frame_async` actually sends synchronously from the calling task — so a slow client's TCP backpressure tied up the esp_timer task, which is shared with every other timer in the firmware. Bursts of broadcasts shared runtime with system timers; a stalled send blocked all subsequent broadcasts. **Architecture** ([Firmware/v1/core/transport/transport.c](Firmware/v1/core/transport/transport.c)):

  - New static `s_broadcast_task` — FreeRTOS task `ll_broadcast`, 4 KB stack, priority 4 (below httpd's default 7, so inbound work always wins runtime contention). Body is a simple `xQueueReceive(portMAX_DELAY) → do_broadcast_state()` loop.
  - `broadcast_timer_cb` no longer calls `do_broadcast_state()` directly — instead posts a token via `enqueue_broadcast("timer-cb")`. The `broadcast_state` fallback (timer-start-failed) now also enqueues rather than running synchronously on the caller's task, preserving the no-block-the-caller invariant.
  - `enqueue_broadcast()` has a fallback for the pre-init window (queue null) that runs the fanout synchronously — only relevant if a broadcast fires before `ll_transport_init` finishes; in practice that doesn't happen because state-bus events aren't subscribed until later.

- [x] [LL-055](tasks.md#LL-055) **Session C — per-IP rate limit (May 15) — LL-055 fix #4 of N, bug-doc fix #3, spec §7.1 closeout.** The spec'd contract had been documented but unenforced ([control-protocol-spec.md §7.1](docs/control-protocol-spec.md): "Per-IP rate limit: 10 messages/sec. Exceeding results in close code 1008"). Sessions A + B made the *steady-state* case responsive; this session adds the *malicious-or-buggy-client* guard so flood traffic gets rejected proactively at the dispatch boundary rather than backpressuring the broadcast task. **Implementation** ([Firmware/v1/core/transport/transport.c](Firmware/v1/core/transport/transport.c)):
  - **Token bucket per peer IP, milli-token math.** Burst capacity 10,000 milli-tokens (= 10 messages), refill 1 milli-token per 100µs (= 10 tokens/sec). Avoids float math on the C3.
  - **Fixed table of 8 entries** (`s_rl_table[]`) — matches the spec's 8-client cap. Lookup is linear scan; eviction on full uses oldest `last_refill_us` so a dormant attacker IP can't squat a slot.
  - **IPv4 from fd via `getpeername`** + `<lwip/sockets.h>`. Handles both `AF_INET` and v4-mapped `AF_INET6` (lwip's default representation); reserves `ip_be==0` as "slot unused" by remapping to `0xFFFFFFFF` if it ever happens to fall on a literal 0.0.0.0.
  - **Single-task access** (httpd's WS handler is single-task) → no locking needed.
  - **Enforced on `HTTPD_WS_TYPE_TEXT` frames only** — control frames (ping/pong/close) handled by httpd directly and don't consume tokens.
  - **Overrun path:** log `WARN`, send WS close frame with code 1008 ("policy violation") via a new `ws_send_close()` helper, then `httpd_sess_trigger_close()` to clean up the framework's session state.
